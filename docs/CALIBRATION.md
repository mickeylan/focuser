# DIY 两点行程标定（不加开关）

## 操作

先关闭 ASCOM 驱动连接及 Alpaca 桥接，避免抢占同一串口。使用完成平台集成的固件后：

```powershell
python host/focus_calibrate.py --port COM7
# 或显式假设备/网络设备：--tcp HOST:PORT
```

这是独立的 Python/Tk 按钮窗口，不需要安装新 GUI 框架；串口仍需原有 pyserial。
启动只查询状态，不自动设零或移动。

1. **手动放到安全内收位置**，距离机械尽头留余量。移动旋钮时注意电机/联轴器是否允许反拖；
   不能强行拧锁死的机构。这个手工位置软件看不到，要由你明确确认。
2. 第一次点击“重新标定：设当前为零位”，确认后累计位置归零。
3. 点击外伸 1/10/100 步按钮。每次走完才能点下一次，接近外端务必用 1 步，观察实际机构。
   必要时内收几步调整，但不允许低于软件零位。**不要撞到机械尽头来测量。**
4. 在安全外伸位置停止，留出余量，点击“记录当前位置为最大位并保存”。只有存储成功才进入正常模式。
5. 关闭标定窗口，再连接 ASCOM/Alpaca。正常 MOVE/GOTO 均由固件限制在 `0..已标定最大步数`，
   不信任上位机配置。ASCOM 的 `MaxStep` / Alpaca 的 `--max-step` 建议同步设为这个步数，
   否则软件可能显示较大范围，但固件仍会拒绝越界，不会按较大值运动。

以后每次上电：先手工回到同一个安全零位，再点击“确认当前为零位（保留最大行程）”。
**重启保留的是最大行程，不是可信当前位置**。即使没有手拧旋钮，也不能跳过重新确认。
中途用手改变旋钮、拆装电机、改变传动比或发现丢步后，停止使用旧位置，重新确认/标定。

窗口关闭会尝试 HALT 并关闭串口。HALT 是串口软件命令，受通信延迟影响，不是硬件急停。
标定时外端尚未知，软件无法判断到头；点动按钮不是堵转保护，观察和预留余量不可省略。

## FP1 命令

| 命令 | 意义 |
|---|---|
| `LIMIT?` | `LIMIT state=0/1/2 max=N`；0=本次上电零位未确认，1=人工标定，2=正常软限位 |
| `ZERO` | 必须停止；将当前设为0，有保存行程则进入正常模式，无行程则进入人工标定 |
| `CALBEGIN` | 必须停止；明确重新标定，当前设0，暂时不用旧外端限制，旧持久记录暂不覆盖 |
| `JOG n` | 仅人工标定，整数 `-100..100`，不含0；禁止替换在途点动，不可跨越0位 |
| `MAXSET` | 仅人工标定且停止，当前位置必须大于0；先保存成功，再作为最大位启用 |
| `HALT` | 所有阶段都可停止，不设零、不自动退出人工标定 |

人工标定固定从100步/秒开始，拒绝将速度提高到100以上；这只是保守的软件默认值，
不是对任何机械机构的安全速度保证。`MOVE/STEP/GOTO` 在未确认或人工标定时拒绝执行，
避免天文客户端后台轮询/自动对焦干扰标定。标定后 JOG 拒绝执行，不能作为软限位旁路。
零位、最大位不能在运动中修改；越界请求返回 `ERR STATE`，不静默夹紧成另一个目标。

## 掉电保存与平台集成边界

当前仓库仍不是完整 STM32Cube 工程。本轮实现了标定逻辑、存储调用契约及 fake HAL 回归，
**没有对真实芯片写 Flash，也没有声称实际掉电保存已经在板子上验证**。

平台需按 `board_stm32f1.h` 实现：

- `focus_board_load_max(int32_t *maximum)`：只在有效持久记录校验通过时返回0。
- `focus_board_save_max(int32_t maximum)`：原子保存并校验成功后才返回0；失败或断电不能破坏旧有效记录。
  使用平台明确预留的 Flash/EEPROM 区域，至少包含版本、数值有效性及完整性校验；不要猜 Flash 尾页。

load失败/无记录/非正值都不能启用正常移动。save失败保持人工标定，不回复成功。
重新启动即使加载最大行程成功，也处于 `state=0`，禁止正常电动移动。
当前采用的RAM替身仅用于模拟重启和保存失败，不能代替真实的非易失存储驱动。

运动中拒绝修改、保存失败保留旧值、保存后两端限位、重启重新确认零位、load失败。

其余C电机/协议、跨语言3项、ASCOM37项仍通过。
